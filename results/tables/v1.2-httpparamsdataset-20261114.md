## Lab corpus diagnostic — not a deployment result

On the 427 expanded training rows generated from the existing 37-case lab corpus, v1.1 predicted 425 labels correctly and v1.2 predicted 372; 53 predictions differ. This set is not an independent holdout. It signals domain shift and a risk of regressions; see the actual RUN-A/B results below. v1.2 is not promoted to the live service.

## Interpretation and limitations

The publisher's train/test split is payload-level, not family-disjoint or collected from this lab's request distribution. The XSS test support is 177, and the high score alone does not establish real-world or WAF effectiveness. The v1.2 `/health` and `/score` endpoints were smoke-checked in an isolated container using the saved artifact and scikit-learn 1.7.1; `/score` returned `lr-tfidf-3cls-1.2`, `degraded=false`.

The first local artifact was serialized under scikit-learn 1.9.1 despite a metrics file later overwritten by a container run. It failed `/score` on the pinned runtime. It was replaced with a freshly trained artifact from the pinned container and the endpoint smoke-check passed. The locked v1.1 artifacts were not modified.

### 37-case comparison against locked v1.1

Both v1.2 runs completed 111/111 case-rounds. RUN-A's per-case results matched locked v1.1 RUN-A (`20261113T105850Z-f4deea31`). In hybrid RUN-B, v1.2 introduced six malicious pass-throughs relative to locked v1.1 RUN-B (`20261113T110057Z-5a65730f`): `de-mal-002` and `de-mal-003` at PL1/PL2, plus `xss-de-mal-001` at PL1/PL2 (all previously blocked by ML, now reached the app with HTTP 200). It also introduced one false positive: benign `xss-pd-ben-001` at PL1 was classified XSS at score 0.572 and blocked. The SQLi true bypass `hpp-mal-004` remains at PL1–PL3. Thus 111/111 means complete evidence, not equal model decisions.

The v1.2 RUN-B runner includes the corrected `pass_without_effect` outcome aggregation. Its `blocked`/outcome fields must not be compared directly with the older locked evidence without accounting for that outcome definition; compare the underlying ML decision, HTTP status, and semantic/browser effect.

An initial RUN-B (`20261114T043506Z-a5b7ae08`) was not used for metrics: the runner stored hybrid evidence but omitted its `ml_enforcement` summary. The runner was corrected and RUN-B was rerun. The initial raw run remains as an audit trail; use only run `20261114T043821Z-4a20ed8b` for the corrected hybrid summary.

After the runs, the shared `waf-ml` service was restored to v1.1. Its health endpoint reports `lr-tfidf-3cls-1.1`; the pinned v1.2 artifact remains available for controlled replay.

Browser verification also exposed and fixed two runner issues: hybrid browser results now update the `ml_enforcement` evidence, and ML-only browser replay compares against `ml_http_status` rather than the CRS HTTP status. Final summaries for both runs have `pending=0`, `incomplete=0`, `control_invalid=0`, and `execution_unverified=0` at every level.

The v1.2 run metadata records commit `ebc8b18`, while the runner fixes described above were present in the working tree and not included in that commit. Treat those runs as evidence for the saved artifacts and recorded requests, with this runner-provenance limitation. The abort `20261114T043141Z-e0f1bf50` and initial RUN-B `20261114T043506Z-a5b7ae08` are superseded and excluded from metrics; the latter had two pending browser checks. Their raw directories are retained for audit.
