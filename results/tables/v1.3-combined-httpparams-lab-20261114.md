# ML-WAF v1.3 — HttpParamsDataset + lab corpus (2026-11-14)

## Training protocol

- Model: `lr-tfidf-3cls-1.3`; Python 3.11, scikit-learn 1.7.1; trained in the pinned Docker image.
- Sources: `Morzeux/HttpParamsDataset` official train split plus the 427 rows produced by `waf-ml/build_dataset.py` from the unchanged lab corpus. Mapping remains `norm -> benign`, `sqli -> sqli`, `xss -> xss`; other external labels are excluded.
- Normalization for duplicate identity: `strip + lowercase`. The external train split had 20,460 mapped rows and 0 internal duplicates. The lab source had 427 rows: benign 223, SQLi 147, XSS 57; 13 normalized duplicates within the lab source were removed. A further 44 lab rows duplicated the external train source and were removed from the combined fit set.
- Combined fit set: 20,830 rows — benign 13,049, SQLi 7,372, XSS 409.
- External test split is used only for reporting, not model selection. Of its 10,228 mapped rows, 17 payloads overlapped the lab corpus and were excluded to prevent train/test leakage. The remaining payload-level holdout has 10,211 rows: benign 6,417, SQLi 3,617, XSS 177.
- A separate normalized-payload audit found no duplicate within the mapped external test split and no overlap between the external train and test splits.
- No lab case was added or edited. The 37-case corpus remains unchanged.

### Comparison with locked v1.1 and v1.2

- RUN-A CRS outcomes and standalone ML decisions/status/effect match locked v1.1 RUN-A (`20261113T105850Z-f4deea31`) on all 111 rows. There are no new misses or false positives relative to v1.1.
- RUN-B's hybrid ML decisions and final response/effect match locked v1.1 RUN-B (`20261113T110057Z-5a65730f`) on all 111 rows. The corrected runner records `pass_without_effect`; the older locked run uses `allowed` for some HTTP-200/no-effect rows. The comparison uses ML decision, HTTP response, and semantic effect rather than matching outcome labels.
- The seven v1.2 hybrid deltas are all resolved in v1.3 and match v1.1:

| Case(s) | PL | v1.2 | v1.3 | Result |
|---|---|---|---|---|
| `de-mal-002`, `de-mal-003` | 1, 2 | ML allowed, HTTP 200, no app effect (`pass_without_effect`) | ML blocked, HTTP 403 | Previous pass-throughs blocked |
| `xss-de-mal-001` | 1, 2 | ML allowed, HTTP 200, no browser execution (`pass_without_effect`) | ML blocked, HTTP 403 | Previous pass-throughs blocked |
| `xss-pd-ben-001` | 1 | ML blocked benign request (false positive) | ML allowed, HTTP 200 | False positive removed; matches v1.1 |

The six malicious rows above were pass-throughs without a demonstrated application/browser effect in v1.2; they should not be described as six successful exploits. In standalone ML RUN-A, v1.3 differs from v1.2 on 27 rows (24 malicious allowed-to-blocked decisions and 3 benign block-to-allow decisions), while matching v1.1 on all 111.

`hpp-mal-004` remains a real SQLi semantic-effect bypass for standalone ML at PL1–PL3 in RUN-A. In hybrid RUN-B, it remains at PL1 and PL2; CRS blocks the request at PL3 before ML. This behavior is unchanged from v1.1 and v1.2.

## Limits

The external split is payload-level, not family-disjoint. The HttpParams CSVs remain git-ignored local inputs; their hashes are recorded here, and a clean checkout needs those source files restored before rebuilding the training image. High holdout metrics do not establish production WAF effectiveness.
