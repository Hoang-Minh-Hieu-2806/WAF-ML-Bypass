# v1.4 XSS dataset augmentation (2026-11-14)

## Scope and source

This is an isolated candidate built from the unchanged v1.3 training sources plus a bounded sample from Mendeley Data v2, [Large-Scale Annotated Dataset for Cross-Site Scripting (XSS) Attack Detection](https://data.mendeley.com/datasets/py6cnbgdh2/2), DOI `10.17632/py6cnbgdh2.2`, CC BY 4.0. The dataset contains 1,831,254 rows with `Query` and binary `Label` (`1` malicious, `0` benign). The source file was read from the user's Downloads folder and is not copied into Git.

The dataset description and its [accompanying paper](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=7649543) state that executable behavior was safety-neutralized and that family/source metadata is not included. Local inspection also found three empty payloads, 97 duplicate payload rows after `strip + lowercase`, and no conflicting labels among those duplicate payloads. Treat its holdout as text-classification evidence, not executable-XSS or family-disjoint validation.

Both runs completed 111 rows (37 cases × PL1–PL3) with v1.4 verified in container health and model metadata. RUN-A's two pending XSS browser checks for `xss-de-mal-001` were resolved as `not_executed` at PL1 and PL2. RUN-B had no pending browser checks.

- All CRS decision, HTTP response, application-effect, and bypass outcomes match the locked v1.1 RUN-A across 111 rows. Compared with v1.3 RUN-A, no standalone-ML block decision changed. `pd-mal-003` changed predicted class from SQLi to benign at all three PLs, but remained blocked because the combined attack score still crossed threshold; this did not change a row outcome.
- All final hybrid decisions and HTTP/effect outcomes match locked v1.1 RUN-B across 111 rows. The 42 rows that reached hybrid ML match v1.3 hybrid model decisions and outcomes; no new lab miss or false positive was observed.
- RUN-A standalone ML blocked all 6 malicious XSS cases and 0/4 benign XSS cases at each PL. This is unchanged from v1.3's lab decisions.
- `hpp-mal-004` remains a true bypass: standalone ML allows it at PL1–PL3; hybrid allows it at PL1–PL2; CRS blocks it before ML at PL3. XSS augmentation did not close this gap.

## Candidate status

v1.4 remains an unpromoted candidate. Keep v1.1/v1.3, the 37-case corpus, and their locked evidence unchanged. The dataset improves the size of the XSS text holdout and adds training diversity, but its neutralized samples cannot prove browser execution. G3 remains **NOT READY** until the existing §6.3 bypass wording and group sign-off are resolved.
