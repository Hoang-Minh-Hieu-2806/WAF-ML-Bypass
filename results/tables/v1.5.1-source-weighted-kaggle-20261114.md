## Data audit

- Mendeley source: 1,831,254 rows (benign 666,484; XSS 1,164,770; no SQLi label). Dedup found 97 exact normalized duplicates, 3 empty rows, 0 conflicting labels. Exact overlap removal excluded 1,138 rows from both Mendeley splits.
- SHA-256 first-byte split `<51/256`, seed 20261115: train 1,464,719; payload holdout 365,297. No family/source metadata exists; near-duplicate and family/group leakage checks are **NOT EVALUATED**. This is payload-level only.
- HttpParams test has 10,228 raw rows; 17 lab-overlap rows are excluded, leaving 10,211. This external split was not used for fitting.
- Fit rows: benign 545,724 / SQLi 7,372 / XSS 932,453 (1,485,549 total). Exact within-source duplicates removed: HttpParams train 0, lab 13, Mendeley 97; combined-fit duplicates 0.
- Weighting: class weights are `None`; one sample-weight vector is passed once to LogisticRegression. HttpParams/lab total weight = 20,830; Mendeley has 1,464,719 raw rows but total classifier sample weight = 12,288 (0.83% average per row). TF-IDF vocabulary and IDF still see all Mendeley fit texts, so source influence is not zeroed at feature fitting.
- Leakage caveat for lab: exact normalized request parameter values from **22/37** cases also occur in the 427-row lab training CSV. The current source-weighted run therefore cannot use those 37 cases as independent proof of generalization. No 37-case candidate run was performed.

## Reviewer questions

1. **Ready for the report?** Yes, as a clearly labeled comparative experiment with the metrics, hashes, and limitations above. No, as the final promoted model or as proof of real WAF-path effectiveness.
2. **Did source weighting improve the model?** Not established. v1.5.1's same-test metrics are close to v1.4 but slightly lower (171/177 vs 173/177 XSS recall; macro-F1 0.9940 vs 0.9960). Since scikit-learn also changed from 1.6.1 to 1.7.1, this is not a controlled source-weighting comparison.
3. **Leakage or overfitting risk?** Exact duplicate checks and payload-level overlap exclusions were applied. Near-duplicate and family leakage are not evaluated because Mendeley has no family metadata. Also, 22/37 lab case inputs overlap lab training data, so those cases cannot independently validate this model.
4. **Generalization evidence?** Partial: an untouched HttpParams test and a Mendeley payload holdout were evaluated. Neither is family-disjoint; executable XSS behavior is not established.
5. **WAF-path evidence?** None for v1.5.1. No candidate RUN-A/RUN-B or browser verification was performed.
6. **Required report limitations?** Payload-level split, no family/source metadata, safety-neutralized XSS payloads, no proof of XSS execution, no independent candidate lab evidence, and source weighting only controls classifier sample weights while TF-IDF vocabulary/IDF still sees all Mendeley training text.
7. **Remaining experiments?** Use a separately versioned training set excluding lab cases for independent 37-case evaluation; run the locked RUN-A/RUN-B and browser checks; run the specified OOF/per-class gates and benign HTML checks; report C4 and SQLi application-effect evidence separately. Do not tune threshold to improve these outcomes.
